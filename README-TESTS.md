# Trophy Shop — 30 автотестов

Набор: **20 Selenium (10 позитивных + 10 негативных)** и **10 обычных pytest (5 позитивных + 5 негативных)**.

## Установка

Скопируйте папку `tests` и три файла из архива в корень проекта рядом с `run.py`.

В окружении проекта установите основные зависимости приложения и тестов:

```powershell
python -m pip install -r requirements.txt
python -m pip install -r requirements-tests.txt
```

## Запуск

Первый терминал:

```powershell
python run.py
```

Второй терминал:

```powershell
python -m pytest tests --collect-only -q
python -m pytest tests/test_pytest_positive.py tests/test_pytest_negative.py -v
python -m pytest tests/test_selenium_positive.py tests/test_selenium_negative.py -v --headed
python -m pytest tests -v --html=report.html --self-contained-html
```

По умолчанию Chrome работает в headless-режиме. Параметр `--headed` показывает окно браузера. Сайт должен быть доступен на http://127.0.0.1:5000. Для другого адреса: `--base-url http://127.0.0.1:8000`.

Тесты Selenium требуют наполненного каталога с хотя бы одним товаром в наличии. Они добавляют и удаляют товары только в собственной браузерной сессии. Негативная проверка checkout намеренно отправляет некорректный email; платёж не создаётся.

Unit-тесты импортируют модели и валидацию Flask, но не создают приложение или записи в БД.

При падении Selenium создаёт скриншот в `test-results/`. Отчёт `report.html` и `test-results/` исключите из Git.

## Важно

Исходная реализация Flask могла измениться после подготовки этого пакета. Если тест падает из-за изменённых имён `data-testid` или формы, исправлять надо селектор под актуальный HTML; если из-за поведения магазина — исследовать баг. Не изменяйте проверки просто ради зелёного результата.

Отрицательный сценарий означает, что некорректный ввод **правильно отклонён**; прошедший негативный тест — это успешная проверка.

Проверку фактической оплаты ЮKassa делать только отдельно в тестовом магазине, с тестовыми ключами.
