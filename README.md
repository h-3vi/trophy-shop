# «Трофей» — интернет-магазин товаров для охоты, рыбалки и туризма

Курсовой проект по теме **«Разработка и обеспечение качества модуля электронной коммерции для магазина товаров охоты и рыбалки»**.

Исходный код: https://github.com/h-3vi/trophy-shop

## Возможности

- Каталог товаров: рыбалка, охота, одежда и обувь, туризм, ножи.
- Поиск по товарам, фильтры по категории, цене и наличию, сортировка.
- Карточки товаров с описанием, фотографией, ценой и остатком.
- Регистрация, авторизация и разграничение прав покупателя и администратора.
- Корзина: добавление, изменение количества, удаление и пересчёт суммы.
- Оформление заказа с контактными данными, адресом и выбором оплаты.
- Интерфейс выбора Яндекс Доставки, СДЭК, Почты России и поиска ПВЗ на карте.
- Административные функции управления каталогом и заказами.
- Демонстрационная оплата; предусмотрена интеграция с ЮKassa.
- 30 автоматизированных проверок (20 Selenium и 10 модульных pytest).

> **Ограничение:** карта помогает найти ПВЗ, но сама по себе не оформляет перевозку у службы доставки. Реальная доставка через API и реальная оплата требуют отдельной настройки договоров, ключей и обработчиков подтверждения.

### Где находятся данные

Приложение получает адрес рабочей БД из `DATABASE_URL`. После перехода на Neon товары, категории, пользователи и заказы находятся **в облачной PostgreSQL**. Файл SQLite сохранён локально как резервная копия и источник для миграции.

Фотографии **не находятся в PostgreSQL**: они хранятся отдельно в `app/static/uploads/`, а в таблице товаров записано имя/путь изображения. Папка с фотографиями исключена из Git, поэтому при переносе проекта на другой компьютер её необходимо скопировать отдельно.

## Подготовка проекта (Windows PowerShell)

Необходимы Python, установленный Git и браузер Chrome для Selenium-проверок.

```powershell
# Из корня проекта
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` укажите свои значения. **Никогда не копируйте реальные пароли в README, чат или публичный репозиторий.**

### Вариант A: облачная PostgreSQL (Neon)

Создайте проект на https://console.neon.tech и скопируйте строку подключения из раздела **Connect**. В рабочем приложении используйте pooled URL. Для драйвера `psycopg` схема начинается с `postgresql+psycopg://`:

```dotenv
SECRET_KEY=ЗАМЕНИТЬ_НА_СЛУЧАЙНЫЙ_СЕКРЕТ
DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST-POOLER/neondb?sslmode=require
PAYMENT_PROVIDER=demo
SITE_URL=http://127.0.0.1:5000
```

Для нового пользователя с пустой БД Flask создаёт таблицы по текущим SQLAlchemy-моделям. Но это **не загружает** ваш каталог и не восстанавливает заказы.

### Вариант B: локальная SQLite

Для автономной разработки можно использовать SQLite:

```dotenv
DATABASE_URL=sqlite:///shop.db
```

Путь SQLite интерпретируется согласно настройкам SQLAlchemy/Flask; используйте явный абсолютный URL, если необходимо открыть конкретную сохранённую базу. Одна лишь пустая SQLite не содержит исходного наполнения каталога.

### Запуск

```powershell
python run.py
```

Откройте http://127.0.0.1:5000. Проверочный маршрут: http://127.0.0.1:5000/health (показывает статус Flask, **не является проверкой соединения с БД**).

Проверить, какая СУБД активна, можно командой (пароль не выводится):

```powershell
python -c "from app import create_app; from app.extensions import db; from sqlalchemy import text; a=create_app(); c=a.app_context(); c.push(); print('СУБД:', db.engine.dialect.name); print('Категорий:', db.session.execute(text('SELECT COUNT(*) FROM categories')).scalar()); c.pop()"
```

Если вы ожидали Neon, в строке `СУБД` должно быть `postgresql`.

## Перенос из SQLite в Neon

Для переноса предназначен корневой скрипт `migrate_sqlite_to_neon.py` (добавьте его в проект, если ещё не сохранён). Используется **прямая** строка подключения Neon — без `-pooler` в имени хоста:

```dotenv
DIRECT_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@DIRECT-HOST/neondb?sslmode=require
SQLITE_SOURCE=instance/shop.db
```

Порядок: сохранить SQLite, остановить Flask, проверить путь к исходной базе, настроить `DIRECT_DATABASE_URL` и выполнить `python migrate_sqlite_to_neon.py`. Скрипт предназначен для **первичного переноса в пустые таблицы**, не для повторного обновления уже заполненной облачной базы. Не запускайте его повторно, если данные уже перенесены.

**Факт выполненного переноса 26.11.2026:** 5 категорий, 101 товар, 2 пользователя, 5 заказов и 7 позиций заказа. Перенос завершился успешно; локальный файл `instance/shop.db` и резервная копия сохранены. Это данные на момент миграции, не постоянно обновляемая статистика.

Для резервирования рабочей PostgreSQL используйте средства Neon или `pg_dump`. Бэкап SQLite **не содержит новых заказов**, созданных уже после переключения на PostgreSQL.

## Автоматизированное тестирование

Подробная инструкция находится в [`README-TESTS.md`](README-TESTS.md).

```powershell
python -m pip install -r requirements-tests.txt
# В другом терминале должен работать python run.py
python -m pytest tests --collect-only -q
python -m pytest tests -v --tb=short --html=report.html --self-contained-html
```

Состав набора: 10 позитивных + 10 негативных Selenium-тестов и 5 позитивных + 5 негативных модульных pytest-тестов. **Последний подтверждённый полный прогон до перехода на Neon:** `30 passed in 40.55s`.

Важное разграничение: модульные тесты и тестовая конфигурация используют SQLite; успешное прохождение 30 тестов **не доказывает**, что все операции на Neon прошли регрессионную проверку. После подключения PostgreSQL отдельно проверьте регистрацию, добавление в корзину и оформление тестового заказа в безопасной тестовой среде. Не проводите такие проверки на реальных пользовательских заказах или оплаченных заказах.

HTML-отчёт `report.html` можно приложить к курсовой, но его лучше хранить локально или в отдельной папке отчётов, а не добавлять в основной исходный код.

## Безопасность

- `.env`, секретные ключи, пароли PostgreSQL и ЮKassa **не должны попадать в Git**.
- Установите случайный `SECRET_KEY` (например, `python -c "import secrets; print(secrets.token_urlsafe(48))"`).
- Поменяйте демонстрационные учётные данные администратора перед публичным развёртыванием.
- Если строка Neon с паролем попала на скриншот или в переписку, **смените пароль роли** в Neon и обновите `.env`.
- `debug=True` и встроенный сервер Flask предназначены для локальной разработки; для публичного размещения требуется production-конфигурация.
- `db.create_all()` создаёт отсутствующие таблицы, но не является полноценной системой миграций схемы: для последующих изменений моделей рекомендуется Alembic/Flask-Migrate.
